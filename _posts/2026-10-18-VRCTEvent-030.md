title: "VRCTEvent v0.3.0"
version: 0.3.0
package: event
tags: [VRCTEvent]
---

- Now requires [VRCTCommon]({{ site.baseurl }}/docs/common/) v0.2.1 or newer
- Unregistering handlers and calling `_CleanupHandlers()` while the emitter is invoking handlers (e.g. from within a
  handler function) is now rejected with an error, as registering already was -
  see [rules & gotchas]({{ site.baseurl }}/docs/event/#rules--gotchas)
- Fixed remaining handlers of an event being invoked with the wrong event name after a destroyed handler was removed
- Fixed registering or unregistering handlers from within a handler function causing other handlers to be skipped or
  invoked twice
- Fixed destroyed handlers halting the emitter instead of being skipped with a warning
- Fixed `_UnregisterHandler(handler)` leaving empty entries behind, causing handler lists to grow indefinitely
- Fixed `_UnregisterHandler(handler)` throwing an exception when called before any handler had been registered
- Fixed `_UnregisterHandler(eventId, handler, eventName)` also removing the last handler registered for the event
- Handler lists are no longer copied on every registration change when there is nothing to clean up
