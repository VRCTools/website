✨ Added
- `AbstractSynchronizedBehaviour.StateInitialized` tells you whether an object has state yet, either because the local owner set it or because it was received from the network - see [state initialization]({{ site.baseurl }}/docs/common/synchronized-behaviour/#state-initialization)
- `AbstractSynchronizedBehaviour.OnStateInitialized()` is a hook that subclasses can override. It runs once, when the state is first initialized

🔧 Changed
- `AbstractSynchronizedBehaviour` now implements `OnDeserialization` - implementations which override it must call `base.OnDeserialization()`
- `synchronizationBackoff` now has a minimum of `0.1` seconds in the Inspector

🐞 Fixed
- `AbstractSynchronizedBehaviour`: a pending synchronization retry could be skipped when the wait timer landed on exactly zero
- `AbstractSynchronizedBehaviour`: an invalid `synchronizationBackoff` is now always logged as an error, even when synchronization debugging is off
- [`ArrayUtils.RemoveElement`]({{ site.baseurl }}/docs/common/utilities/#arrayutils): the returned array was filled with the removed element instead of the remaining ones

📚 Documentation
- Subclasses of `AbstractSynchronizedBehaviour` must call the base implementation of every method they override
- `_EnsureOwnership()` now explains that changing values before the state is initialized may reset them to their defaults
- `ArrayUtils.AddElement` now explains how it differs from `AddElementOrCreate`
